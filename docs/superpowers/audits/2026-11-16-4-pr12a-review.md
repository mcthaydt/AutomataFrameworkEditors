## Red: 2

### 1. On a phone the picked tool's ring is drawn over its name, and long names run into each other

UNIT: `src/features/shell/Toolbar.svelte`, the `max-width: 440px` rules; the toolbar test in
`tests/journeys/settings-and-join.journey.test.ts`.
VERDICT: red.
REQUIREMENT: cycle 3's red 2 and red 1, "no name is cut" and the test's own claim, "with its names readable"; the
drunk-grandma test.
REASON: `padding: 4px 0` lets a name be exactly as wide as its button, so the picked state's 2 px inset ring
(`.tool.on`, `box-shadow: inset 0 0 0 2px var(--accent)`) crosses its first and last letters, and neighbouring names are
2 px apart, so they read as one line.
EVIDENCE: `toolbar-ru-phone.png` (the journey's own picture at `0f09966`), zoomed: the peach ring runs through the "В"
and the "ь" of the picked "Выбрать", and "Выбрать Поставить Стереть Соединить" reads as one sentence; text and button
edges coincide to 0.1 px for the six names above. The check passes because it allows the text up to the button's
outer edge.
EXPECTED: every shown name sits inside its button with room for the ring, at least 2 px clear of each side, in all
nine languages, with every tool still at least 44 px and on screen. The check fails otherwise.
FIX: the test's `cut` measures against the button's box inset by 2 px (`words.left < box.left + 2 ||
words.right > box.right - 2`, keeping the 0.5 px slack if wanted); then the four tools' side padding in the phone rules
(for example `4px 3px`; ru has about 35 px to spare across the row) or a smaller gap's worth elsewhere in those rules.
Files: that journey, `src/features/shell/Toolbar.svelte`.

### 2. The toolbar test measures before the fonts are in

UNIT: `tests/journeys/settings-and-join.journey.test.ts`, test 'the toolbar of every language is wholly on screen, with
its names readable'.
VERDICT: red.
REQUIREMENT: CLAUDE.md "How code is written": "Browser tests wait on readiness".
REASON: after each reload the test waits only for `crate-1`, then measures; the page's fonts are often still loading,
so it can measure the names in a fallback font.
EVIDENCE: the probe, three runs: `document.fonts.status` was `loading` at the moment the test measures in en, ko, ja,
pt, fr, ru or de on one run or another, and in ko, ja and de the measures changed after `document.fonts.ready` (de
"Verbinden" button 163.5 to 216.8, then 163.9 to 216.2; ja "やり直す" text to 382.3, then 381.5). Today the change is
under 1 px and the test passes both ways, but a name close to its limit could pass or fail by the font, not the layout.
EXPECTED: the test measures only once the fonts are in.
FIX: `await settled(page)` (already in the file; it waits for `document.fonts.ready` and two frames) before the
`page.evaluate` that measures. Files: that journey only.
